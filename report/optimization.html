Port and optimization results · trn2.48xlarge · Neuron SDK 2.33

Strands Decider 2B on Trainium2

A from-scratch PyTorch re-implementation of the decider torso and readout, compiled with the SDK 2.33 PyTorch-native backend. Three custom NKI kernels and the nkilib attention kernel do the heavy lifting. The port is verified against the CPU fp32 reference on 1,019 labeled rows and 54 request-level answers.

1. Summary

The decider runs on Trainium2 as one compiled graph per (T, B) bucket. The graph covers the embedding gather, all 24 layers, the final norm and the fp32 pointer readout, and returns calibrated probabilities [B, K] to a host engine that reuses the reference implementation's prompt, window and read-back code.

Three steps took the full model from 174.3 ms to 67.3 ms at T = 2,048 on one logical core (20.3% → 52.8% MFU). First, head-major projection layouts (v1). Then fused NKI prologue, epilogue and norm kernels with pre-transposed GEMM weights (v2). Finally a new WY-form Gated DeltaNet kernel, gdn_fast, 2.4× faster than nkilib's gdn_cte (v3).

64 data-parallel replicas deliver 1.71M tokens/s per trn2.48xlarge at 46.0% MFU. For long requests, a TP2 pair inside one chip cuts T = 4,096 from 133.6 to 87.9 ms. Every configuration passes the accuracy gate against the CPU fp32 golden, and changes none of the 54 reference answers.

Gotchas that cost time (docs/native_stack_howto.md §7)
  • G1: set VLLM_NEURON_BACKEND=neuron_native before importing libtorch_neuronx_lite. If it is unset, lite takes the XLA route with no precompile cache, silently.
  • G2: NEURON_RT_ROOT_COMM_ID is required even for a single-core matmul at LNC = 2. Use the same value within a TP group and distinct values across groups.
  • G3, G4: torch.neuron.synchronize() does not wait for execution, so block with .cpu() or a fence graph. More than 8 queued executions fail unless NEURON_RT_XU_COMPUTE_MAX_QUEUED_REQUESTS is raised (32).
  • G5: NEURON_RT_IO_RING_CACHE_SIZE=32 removes a per-execution DMA-descriptor rewrite (gdn_cte 3.15 → 1.19 ms per call).
  • G8: vllm-neuron's NF.* ops fall back to torch silently. For this model that happens at TP = 1, and for D = 256 attention at any TP. Call nkilib through wrap_nki directly.
  • G9, G10: the 9th distinct shape on one compiled callable fails (recompile limit 8). The Dynamo precompile cache ignores compiler-flag changes; delete TORCHINDUCTOR_CACHE_DIR when changing flags.

3. Implementation architecture

Weights, prepared once at load (decider_model.load_state, fused_ops.prepare_*)

  • LoRA merged: W += (α / r) · B A with α / r = 96 / 48 = 2, formed in fp32 and cast once to bf16. Zero runtime cost.
  • Base weights rounded to bf16 first, as HF loads them (the fp32-stored norm weights and A_log included). Zero-centred RMSNorm weights are folded to 1 + w; the GDN gated norm keeps its plain weight.
  • Head-major layouts: GDN q | k | v | z become one [64, 128, 2,048] tensor (16 heads each), so one einsum lands directly in [B, H, T, 128]. b | a become [32, 2,048]. Attention becomes [20, 256, 2,048] = q (8) | gate (8) | k (2) | v (2). q_proj is de-interleaved per head, because its rows are [q_h | gate_h] per head.
  • Pre-transposed [K, N] GEMM weights, plus conv taps as diagonal matrices for the tensor-engine conv, and (A, dt_bias) packed per head.

Graph and engine

  • Right-padded batches with no padding mask. Causal attention and the causal recurrence make tail pads invisible to real positions. The readout gathers the last real token and the option tokens by index.
  • Buckets (EngineConfig): T ∈ {256, 512, 768, 1,024, 1,536, 2,048, 2,560, 2,816, 3,072, 4,096}. Batch sizes are {1, 2, 4, 8} at 256, {1, 2, 4} at 512, {1, 2} at 768 and 1,024, and 1 above. The engine picks the smallest compiled B that holds the remaining rows.
  • Shared prefix: the state is encoded once in a prefix bucket. Each GDN layer returns its final fp32 state and the last 3 pre-conv tokens; each attention layer returns K and V. Suffixes of ≤ 128 tokens then run in batches of 2, 4, 6 or 8. Prefix pads are made exact no-ops: β = 0 and g = 0 on pads (the state passes through unchanged), the conv tail is taken before the real length, and K/V beyond prior_len are masked. Bucketing the prefix is therefore exact.
  • Tensor parallel (shard_state, tp_runner.py): Megatron-style column/row splits by head and by MLP column. Each rank keeps its own heads' GDN and conv states. Out-projection and MLP partial sums are all-reduced in graph. An optional split of each layer's tail into token chunks gives the scheduler independent all-reduce chains.

5. Kernel deep dives

5.1 gdn_fast: a WY-form chunked Gated DeltaNet kernel

The evidence. neuron-explorer profiles at B = 1, H = 16, T = 2,048 (kernels/test_gdn_fast.py notes) show that nkilib's gdn_cte is limited by instruction overhead, not arithmetic. It issues 28 matmuls per chunk, 2 of them fp32 at ~184 ns average, and about 40 unbatched [128, 128] vector and scalar ops at 283 / 280 ns each, of which 65 ns (DVE) and 290 ns (ACT) is fixed cost. Lanes are emitted one after another. Its host wall time was 2.9 ms per call, of which ~1.8 ms was the runtime rewriting static (dge_mode=none) DMA descriptors on every execution.

What changed (kernels/gdn_fast.py):

  • WY form. The Schur-complement inverse is applied to [βv | β e^G k] once per chunk, off the recurrence. The sequential path per chunk shrinks to 4 matmuls and 2 vector ops: δ = u − wS; out = (scale·e^G q)S + Wδ; S′ = e^{G_last}S + (e^{G_last − G} k)ᵀ δ.
  • Four lanes per instruction. Every vector and scalar op runs on [128, 4 × 128] operands, one PSUM bank, which amortises the ~65 ns (DVE) and ~290 ns (ACT) fixed cost that dominated [128, 128] ops. Identity-stationary matmuls are batched to N = 512.
  • Level-major scheduling. Jobs (4 lanes × 1 chunk) are emitted in batches, with the previous batch's state updates interleaved between the 7 inverse levels, so every engine has independent work. B = 1 has only 8 lanes per NeuronCore.
  • Cheaper inverse and decay. The off-block mask is applied on the PSUM evacuation, and the inverse accumulates in fp32 PSUM across the 7 levels. Decay matrices come from a K = 3 broadcast matmul (an exact bf16 hi/mid/lo split of G) and one masked exp per lane, with β and the query scale folded into the exp bias. There are no fp32 matmuls per chunk.
  • All DMAs DGE-generated. No per-execution descriptor rewrite is needed.

5.2 The fused GDN prologue and epilogue

gdn_prologue_kernel replaces depthwise conv1d (K = 4), SiLU, the L2 norm of q and k, and β/g with one NKI kernel. The conv and the feature-major to token-major transpose are a single tensor-engine op per 128-token block and tap: the stationary operand is the shifted input, the moving one is diag(w_j), and PSUM accumulates the 4 taps in fp32, which is exact for bf16 operands. SiLU runs on ScalarE straight out of PSUM. VectorE computes the sum of squares, and GpSimd the rsqrt (ULP-1, against ~4e4 ULP for ScalarE's). Alternatives were all 10–30% slower at T = 512–4,096: a feature-major conv with shared tap loads plus PE transposes, an on-chip diag(w), per-head stores at long T, and ScalarE squares.

5.3 The norm-fusion compiler finding

Finding

When neuronx-cc fuses an RMSNorm into a head-major (feature-major) einsum, that GEMM runs 2–3× slower: 1.13 ms against 0.58 ms at T = 2,048 in one measured context. Running the norm as an NKI kernel puts a custom-call boundary in front of the GEMM and avoids the fusion. In front of the token-major MLP GEMM, the compiler fuses the torch RMSNorm well, so the MLP keeps it in torch. The effect depends on context: inside gdn_in_proj the two variants are within ~5%.

5.4 attention_cte at head_dim 256

vllm-neuron's NF.flash_attention gates on D ≤ 128 and silently falls back to torch for this model. The nkilib kernel itself tiles d up to 512, and it works when called directly through wrap_nki: GQA is native, causal, with an fp32 softmax. tp_k=False (K laid out [B, D, S]) is fastest.

6. Accuracy

6.1 Method, and why the gate was re-based

  • Golden tensors (tools/make_goldens.py): the CPU fp32 HF + PEFT reference, run through the repo's own evaluation path (SystemOneCollator(train=False), no option shuffling) on the committed labeled eval sets (generated_v18_eval, generated_v16_eval, adequacy_gen_eval, flips_v20_eval). One example runs per forward, unpadded. Each golden stores token ids, option positions, label, logits, calibrated probabilities, and the final-norm hidden states at the readout positions: 1,019 rows over 22 tasks. The golden reproduces the model card's per-task accuracies where the sets coincide: gen:cross_artefact 0.710 (n = 31), gen:missing_fact 0.724 (n = 29).
  • The gate (neuron/accuracy.py) compares the device's calibrated probabilities with the golden, row by row. It also compares accuracy, ECE (10 bins, server confidence) and NLL against the labels, for device and golden alike.
  • The bf16 floor. Running the same re-implementation in bf16 on CPU drifts up to 0.016 in max |Δp| on 24 rows, row for row like the device. A bf16 implementation cannot be held to fp32 agreement. So the bounds were re-based on that measured floor, to separate "bf16" from "bug": mean |Δp| ≤ 0.005, p99 ≤ 0.02, max ≤ 0.05, argmax flips only where the golden top-2 margin is < 0.05, accuracy within 0.5 pp, ECE within 0.01, NLL within 0.005.
  • Why re-based, concretely. The first full v1 run (gate_full_v1.json) records PASS: false. Every aggregate was well inside the bounds, but one argmax flip at golden margin 0.022 counted as "not a near tie" under the stricter threshold then in force. A drift of up to 0.016 per probability, with two probabilities moving in opposite directions, can produce a flip at a 0.022 margin. Under the floor-based gate the same run passes.

6.2 Per-op equivalence on real activations

neuron/equiv_layer0.py feeds every implementation the same fp32-reference input of each op, so errors do not propagate, using real activations of layer 0 (GDN) and layer 3 (attention) at T = 512. It reports relative L2 error against fp32 for CPU bf16 and for the device.

The transcendentals (l2norm, sigmoid, softplus, exp, rsqrt in fp32) are exact on the CPU-bf16 path and at most 9e-7 on device. The GDN core is the one op above CPU bf16 (2.07e-3 against 0.90e-3, the nkilib kernel in this run). Running the GDN core in fp32 does not change the end-to-end drift.

8. Recommended deployment (trn2.48xlarge)

Deployment
  • Single-core (LNC2) data-parallel replicas, with dynamic batching per bucket (B × T ≤ ~2,048 tokens) for short requests. Buckets: 256 / 512 / 768 / 1,024 / 1,536 / 2,048 / 2,560 / 2,816, plus 3,072 / 4,096 on TP2.
  • A TP2 pool (adjacent logical cores in one chip) for requests over ~2.8K tokens, and for multi-question requests whose state is longer than ~2K tokens. Use 4-way chunked all-reduce, prefix buckets that include 2,560, and suffix batches of {2, 4, 6, 8}.
  • JevBench's length distribution (p50 178, p90 2,471, p99 3,072 tokens) puts 96.6% of requests on the DP pool: 72% are ≤ 512 tokens and 86% ≤ 2,048.
  • Use the shared-prefix path for every multi-question request.
  • Runtime environment: NEURON_RT_IO_RING_CACHE_SIZE=32, NEURON_RT_XU_COMPUTE_MAX_QUEUED_REQUESTS=32; set TORCH_CACHING_PRECOMPILE=0 when iterating on kernels.

9. Limitations and next steps

  • TP2 at T = 4,096 is communication-bound at ~41% MFU. The in-graph all-reduce costs 402 µs per 16 MiB, 48 times per forward, with no overlap. The cost model, recalibrated to the v3 kernels and to in-graph collective cost (cost-model report), ranks CP2 with the two-pass GDN state correction best for long prompts: 81.5 ms and 44.0% MFU at T = 4,096, against 91.1 ms modelled and 87.9 ms measured for TP2. CP's only traffic is the K/V and GDN-state all-gathers, about 1.9 ms per forward, against TP2's 19.2 ms of all-reduces. CP2 is therefore the recommended next implementation step; TP2 is what is implemented and measured today. The CP2 prediction is unvalidated: its first step should measure in-graph all-gather at 4–8 MiB. Other options:
    • An NKI q/k-norm + RoPE kernel for the attention layers. With the core stubbed out, the rest of the attention layer still takes 1.07 ms at T = 2,048, and its non-GEMM part is the torch q/k RMSNorm and partial RoPE.
    • Integration as a vLLM-neuron plugin, to inherit its executor, scheduling and serving stack. Its MPExecutor and parallel-state groups were read but not run here.
  • The fp16 GDN mode is measured and passes the gate with golden-equal accuracy at +2% latency. It is an accuracy option, not yet the default.
  • Coverage gaps. No 2-rank nccom-test data exists, so the cost model uses a 4-rank proxy. In-graph RS, AG and A2A were measured only as RS + AG at world 2. Multi-node and EFA were not tested. The 2,816 bucket is used end to end but was not separately benchmarked in the bench JSONs.
  • Cold compile takes 16–157 s per bucket (bench JSON compile_s), so every bucket must be warmed at start-up. Warm caches load in about 1 s.
