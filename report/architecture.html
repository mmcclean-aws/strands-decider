1. Executive summary

What it is. Strands Decider is a "System One" decision model. A request carries a state (text or JSON) and one or more typed questions. The model returns, for each question, a probability distribution over the options that question lists. There are three question kinds, and all three use the same mechanism: noul (yes/no; returns P(true)), choice (2 to 255 named options; returns the argmax, the probabilities and a confidence) and score (2 to 10 ordered levels; returns the expected level, the distribution and a confidence).

How it is built. The torso is the text decoder of Qwen/Qwen3.5-2B-Base: 24 pre-norm residual layers with hidden size 2,048. 18 layers use Gated DeltaNet, a linear-attention token mixer that carries a fixed-size recurrent state. The other 6 use gated full attention (GQA 8:2, head_dim 256, QK-norm, partial RoPE, a sigmoid output gate). Every layer has a dense SwiGLU MLP, 2,048 → 6,144 → 2,048. There is no mixture of experts. LoRA adapters (r = 48, α = 96) sit on every projection of both mixer types and on the MLPs, and they can be merged into the base weights. The language-model head is never loaded. Instead, a 3.15M-parameter pointer head in fp32 scores option k as a scaled dot product between a query built from the hidden state of the prompt's final token (the > of <answer>) and a key built from the hidden state of the last token of option k's line. A per-kind temperature and a masked softmax turn those logits into probabilities.

Why it is cheap. A request is one prefill forward. There is no autoregressive decode loop, no sampling, and no KV cache that outlives the request. The output side is one distribution per question (usage.output_tokens equals the number of questions). When a request asks more than one question, the engine encodes the state once, forks the per-layer state (attention K/V, and the GDN convolution and recurrent states) across the questions, and forwards only the short question suffixes.

For the port

Dense GEMMs (the MLPs and the token-mixer projections) account for 94–97% of the FLOPs, from L = 4,096 down to L = 256 (§9). The engineering risk lies elsewhere:

  1. A chunked Gated DeltaNet kernel and its depthwise causal conv1d, with an fp32 recurrent state.
  2. Attention with head_dim 256, which exceeds one 128-row partition tile, plus partial RoPE (64 of 256 dims), QK RMSNorm and an output gate. The q_proj rows are interleaved per head.
  3. Exact numerics: zero-centred RMSNorm x·(1+w) everywhere except the GDN gated norm, an fp32 state, and an fp32 readout.
  4. Static-shape bucketing that pads without corrupting a recurrent state that will be reused.

The model is prefill-only, so no decode kernels are needed.

2. End-to-end inference path

The diagram follows one request through the serving engine (SystemOneEngine.evaluate in infer.py). The middle lane is what a Trainium port must run. The fp32 tail can run on the device, as infer.py does, or on the host, as hidden_engine.py does.

Prompt rendering

render_state wraps the state in <state>…</state>; a dict or list state is first serialised with json.dumps(indent=2). render_question emits a kind-specific header, the instructions, and a numbered options block with one line per option, k. name — description. Descriptions are collapsed to a single line so that each option is exactly one line. The question ends with <answer>. Options are not shuffled at inference. Here is the routing example from docs/architecture.md, with the four positions the readout reads highlighted:

<state>
Help! My payouts have been failing for 3 days.
</state>
<question type="choice">
Select exactly one option.
Which team should handle this?
<options>
1. billing — payments, invoices, payouts
2. technical — bugs, outages, API errors
3. sales — pricing and upgrades
</options>
</question>
<answer>

Run through the checkpoint's tokenizer, this prompt has 21 state tokens and 65 question tokens, so L = 86. No BOS token is added: the first token is <. <answer> splits into three tokens, < answer >. The decide vector is the hidden state of the final >, because pool_last_token takes the last unmasked position.

Window fitting

prompting.fit_window tokenizes the state (add_special_tokens=True) and each question (add_special_tokens=False). If len(state) + longest_question > max_length, it raises; the server answers HTTP 422. With max_length = 4096, every forwarded sequence is at most 4,096 tokens. The brief and docs/architecture.md say that the state is "cut from the front" at serving time, but no truncation exists in the code (Appendix A, item 1). If a question's option list were ever truncated, option_token_index would raise rather than score an option from a neighbour's representation.

Answers and confidences

noul P(true) = p[slot labelled "true"] # slots are rendered (false, true) choice answer = argmax_j p_j conf = clamp((N·p_max − 1) / (N − 1), 0, 1) # 0 uniform, 1 one-hot, N-independent score E = Σ_i i·p_i # levels 0 … L−1, ascending σ = sqrt(Σ_i p_i·(i − E)²) σ_max = (L − 1)/2, σ_floor = sqrt(ordinal_smoothing) = sqrt(0.1) conf = clamp((σ_max − σ) / (σ_max − σ_floor), 0, 1) # guard: if σ_max ≤ σ_floor, conf = 1 when σ ≤ σ_floor, else 0

The score confidence is not 1 − σ/σ_max. The floor correction stretches the scale, so that a model trained with 10% ordinal smoothing can still reach 1.0 (schema.derive_score_confidence). All three are host-side scalar arithmetic on at most 255 probabilities.

4. Gated DeltaNet deep dive

Gated DeltaNet (Qwen3_5GatedDeltaNet) replaces softmax attention with a linear recurrence on a per-head 128 × 128 matrix state. Each token decays the state, writes a correction to it with the delta rule, and reads it with its query. 18 of the 24 layers use it. Its cost per token is constant in L, and its "cache" is a fixed 1 MiB fp32 state per layer per sequence, plus a tiny convolution tail.

4.2 Recurrent form (the definition)

For each of the 16 heads, independently, and each token t (torch_recurrent_gated_delta_rule):

q̂_t = l2norm(q_t) / √128 k̂_t = l2norm(k_t) # l2norm(x) = x·rsqrt(Σx² + 1e-6), fp32 β_t = σ(b_t) g_t = −exp(A_log)·softplus(a_t + dt_bias) α_t = exp(g_t) ∈ (0, 1) S_t = α_t·S_{t−1}·(I − β_t k̂_t k̂_tᵀ) + β_t·v_t k̂_tᵀ # S as [d_v × d_k] o_t = S_t·q̂_t # reads S AFTER this token's write # HF stores the transpose, S as [d_k × d_v]: # S ← α·S; δ = β·(v − Sᵀk̂); S ← S + k̂·δᵀ; o = Sᵀq̂ y = out_proj(RMSNormGated(o, z)) RMSNormGated(o, z) = o / sqrt(mean(o²) + 1e-6) · w ⊙ SiLU(z) # per head, over 128

The delta rule reads the state's current prediction for key k̂_t, Sᵀk̂_t, and writes only the correction β(v_t − Sᵀk̂_t). The decay α_t is a learned, input-dependent forgetting factor. Because k̂ and q̂ are unit-norm and α, β ∈ (0, 1), the state stays bounded. That bound is what lets kernels use bf16 matmul operands while keeping the state itself in fp32.

4.3 Chunked (WY / UT-transform) form, as in torch_chunk_gated_delta_rule

Prefill cannot afford L sequential rank-1 updates, so the reference splits the sequence into chunks of C tokens (C = 64, the function's default; the caller does not override it). It pads the sequence to a multiple of C. Padding uses q = k = v = 0, β = 0 and g = 0, which leaves the state unchanged. Inside a chunk, with cumulative log-decay γ_i = Σ_{j≤i} g_j, and Q, K already normalised and scaled:

Γ_ij = exp(γ_i − γ_j) if j ≤ i, else 0 # masked to −inf BEFORE the exp (no overflow) K_β = diag(β)·K, V_β = diag(β)·V A = (K_β Kᵀ) ⊙ Γ T = (I + strict_lower(A))⁻¹ # solve_triangular(…, unitriangular=True) U = T·V_β # "new values" (u) W = T·(K_β ⊙ e^γ) # "k_cumdecay" (w) P = (Q Kᵀ) ⊙ Γ # intra-chunk attention, incl. diagonal # then sequentially over chunks n = 0 … N−1, with S stored [d_k × d_v], # Q̃ = Q ⊙ e^γ and K̃ = K ⊙ e^(γ_C − γ): V′ = U − W·S O_n = Q̃·S + P·V′ S ← e^(γ_C)·S + K̃ᵀ·V′

The explicit-inverse form gives 180,224 FLOP per token per head at C = 64 and 262,144 at C = 128. Over 16 heads that is 2.88 MFLOP (C = 64) or 4.19 MFLOP (C = 128) per token per layer. The HF reference solves the triangular system twice instead of forming T (8CD + 6D², 2.62 MFLOP at C = 64). Forming T is extra, and how much it costs depends on the algorithm; it is excluded here. The conv1d adds 8 FLOP per channel per token (49k FLOP per token per layer) of vector work.

The depthwise causal conv1d

out[c, t] = SiLU( Σ_{j=0..3} w[c, j]·x[c, t − 3 + j] ) x[c, t < 0] = 0, c ∈ [0, 6,144)

During a cached continuation (the shared-prefix suffix pass), HF concatenates the cached last 4 raw columns in front of the new columns, convolves, and keeps the last seq_len outputs. A port must store the pre-conv projection output, not the post-SiLU values.

4.4 Why it is hard on accelerators

  • A sequential scan. Phase 2 is a dependency chain of ⌈L/C⌉ steps per layer. Within a step, the parallelism is only 16 heads × batch, on 128 × 128 operands. Larger C means fewer steps but more intra-chunk work (10CD per token grows with C).
  • A triangular inverse per chunk. Forward substitution is serial in the chunk index, so kernels restructure it as block doubling or a Schur-complement merge. The numerics are treacherous. mps_kernels.py records that a Neumann product (I−N)(I+N²)(I+N⁴)… passed random-input tests yet was wrong by up to 5e8 on real Qwen3.5 activations, because correlated, L2-normalised keys make the powers of N huge before they cancel. Recursive block inversion was correct.
  • Mixed precision. The state accumulates across the whole sequence and must stay fp32. The decays exp(γ) span many orders of magnitude within a chunk, so the masking must happen before the exp. The HF reference runs the entire core in fp32; fused kernels (FLA, nkilib) use bf16 matmul operands, which is safe only because q and k are L2-normalised first.
  • Many small elementwise ops. These are l2norm, softplus, exp, sigmoid, masking, the cumulative sum, and the gated norm. On Trainium they land on the vector and scalar engines, so fusing them matters more than their FLOPs suggest.
  • Layout changes. The conv runs channel-major ([6,144, L]: channels on partitions, time on the free axis). The core wants head-major [16, L, 128] tiles, and the gated norm wants [L·16, 128] rows.

5. Gated full attention deep dive

Layers 3, 7, 11, 15, 19 and 23 use Qwen3_5Attention: causal softmax attention with four additions to a vanilla block. These are a per-head sigmoid output gate produced by the same projection as the query, RMSNorm on each Q and K head, rotary embedding on only the first 64 of 256 dims, and grouped KV heads.

[Q̃_h | G_h] = (q_proj·x)[h·512 : (h+1)·512] # per head: 256 query rows, then 256 gate rows Q_h = RoPE₆₄(RMSNorm₀(Q̃_h)) # RMSNorm₀(x) = x/rms(x)·(1 + w), w ∈ R²⁵⁶ K_g = RoPE₆₄(RMSNorm₀((k_proj·x)_g)), V_g = (v_proj·x)_g, g = ⌊h/4⌋ O_h = softmax(Q_h K_gᵀ / 16 + M_causal)·V_g y = o_proj(concat_h(O_h) ⊙ σ(concat_h(G_h)))

Multimodal RoPE reduces to plain 1-D RoPE for text

Qwen3_5TextModel.forward builds position_ids with four rows: text, T, H and W. The text row feeds the causal mask; the T/H/W rows feed the rotary module. recomposition_frequencies picks, for each of the 32 frequencies, which stream drives it, interleaved by mrope_section [11, 11, 10]: j ≡ 0 (mod 3) uses T, j ≡ 1 uses H, j ≡ 2 uses W. For text-only input, all streams are the same arange, so the result is ordinary 1-D RoPE with p = token position. Positions are arange(L) on the batched path and L_s + arange(L_q) on the suffix pass of the shared prefix (taken from the cache length).

For the port
  • head_dim 256 versus 128 partitions. The QKᵀ contraction over d = 256 must be split into two 128-row tiles accumulated in PSUM. PV produces a 256-wide free dim. The nkilib attention_cte in ext/nki-library already tiles d (_D_TILE_SZ = 128, _MAX_HEAD_DIM = 512). Kernels that assume d ≤ 128 need that tiling added.
  • RoPE lives entirely in d-tile 0 (dims 0–63). Tile 1 needs no rotation.
  • q_proj must be de-interleaved per head to split W_q and W_gate. A plain first-half/second-half split is wrong.
  • Fuse the output gate O ⊙ σ(G) into the o_proj input. Keep the QK-norm before RoPE, and cache K after both.

6. MLP: dense SwiGLU, no MoE

MLP(x) = W_down·(SiLU(W_gate·x) ⊙ (W_up·x)) # W_gate, W_up: [6,144, 2,048] W_down: [2,048, 6,144] no bias

Every one of the 24 layers has this MLP (Qwen3_5MLP). There is no mixture of experts: mlp_only_layers is empty, and the checkpoint holds only gate_proj, up_proj and down_proj per layer, with no router and no expert weights. Each MLP has 37.75M parameters, 906M in total (66% of the non-embedding parameters), and costs 75.5 MFLOP per token, about 64% of all FLOPs at L = 1,024. It is a textbook GEMM–activation–GEMM. Fusing gate and up into one [12,288, 2,048] GEMM with a SiLU-multiply epilogue is the standard treatment.

Porting trap

Feeding the Qwen3.5 torso norms into a standard x · w RMSNorm kernel without adding 1 to the weights breaks the model. Adding 1 to the GDN gated norm's weight breaks it as well. Fold (1 + w) into the stored weight once, offline, for the five zero-centred norm sites.

Other particularities

  • Tied embeddings. embed_tokens [248,320, 2,048] holds 508.6M parameters (1.02 GB in bf16). The tied LM head is never used: the loader keeps Qwen3_5ForCausalLM.from_pretrained(...).model, the decoder only. The table is only gathered from, at most 4,096 rows per sequence, so it can stay in HBM untouched by compute, or even live on the host.
  • Discarded components. The base checkpoint holds 2,274,069,824 parameters in all. Beyond the text model, that includes a 331.4M-parameter vision tower (model.visual.*) and a 60.8M-parameter multi-token-prediction block (mtp.*, ignored on load). The text engine refuses images.
  • LoRA. r = 48 and α = 96 give a scale of 2.0. The adapter covers 12 module types (q/k/v/o_proj, gate/up/down_proj, in_proj_qkv/z/a/b, out_proj) with 372 tensors and 50,457,600 parameters, stored in fp32. The torch path keeps it unmerged: PEFT computes the delta in fp32 beside the bf16 base GEMM. Merging gives W′ = W + 2 · B A, formed in fp32 and rounded once to bf16, as mlx_engine.merge_lora does. docs/inference.md measures the cost of merging on MLX: no answer changes, and the largest probability difference against the fp32 CPU reference is 0.0138, of which 0.0105 is attributed to merge rounding.
  • A three-seed soup. train_config.json records r = 16 and pointer_dim = 256. training/soup.py stacks three seeds: r = 3 × 16 = 48, pointer_dim = 3 × 256 = 768, and each head's LayerNorm affine is folded into its projections, so the logit is exactly the mean of the three heads' logits. This has no runtime consequence, but it explains why the LayerNorm has γ = 1 and β = 0.
  • Small fp32 parameters. A_log and linear_attn.norm.weight are fp32 in the file, and dt_bias is bf16. The reference loader casts all of them to bf16, which was verified by loading a tiny Qwen3.5 with dtype=bfloat16 under transformers 5.17. To match the reference bit for bit, round A_log to bf16 before computing g in fp32.
  • Padding. apply_mask_to_padding_states zeros the GDN input at padded positions, but only when the 2-D mask is not all ones. Both serving paths right-pad.
  • Attention implementation. Qwen uses the transformers default (SDPA). The eager override in serving_attn_implementation applies only to Gemma 4 E2B.

8. Pointer readout, question types, shared-prefix cache

8.1 The pointer head

x̄ = LayerNorm(h) q = W_q·x̄_dec + b_q ∈ R⁷⁶⁸ k_j = W_k·x̄_opt,j + b_k ∈ R⁷⁶⁸ ℓ_j = (q·k_j) / √768 / T_kind p = softmax_{j<N}(ℓ) # fp32 throughout; each projected row costs 2 × 2,048 × 768 ≈ 3.1 MFLOP

Why these positions: the torso is causal, so the final token is the only one that has read the whole prompt, and the last token of an option's line is the first token that has read that entire option. The head stays in fp32 because a low-precision classifier is "a needless source of calibration error" (modeling.build_head). Its total cost is about 3.1 MFLOP per question plus 3.1 MFLOP per option, which is negligible next to the ~243 GFLOP torso pass for the 86-token example.

8.3 The shared-prefix cache

When it is used. evaluate splits the questions into chunks of at most max_batch (32), optionally cut further by max_batch_tokens, and re-fits the state for each chunk. A chunk with a single question always takes the batched path: infer.py measured p50 0.111 s batched against 0.204 s through the prefix path for single-question requests. A request with more than 32 questions encodes its state once per chunk.

The fork copy is m × (18 MiB GDN state + 0.84 MiB conv state + 12 KiB × L_s KV). It is a real allocation and copy, and a port can avoid it. Each suffix row only reads the prefix state as its initial value, and the suffix's final states are never used, so a read-only broadcast of the batch-1 prefix state is equivalent. One caveat: nkilib's gdn_cte updates a supplied recurrent_state in place. With that kernel, each row needs its own copy, or the kernel needs a read-only initial-state variant.

9.2 FLOPs

Convention: 2 FLOPs per multiply-add, counting matmul-class work only. Norms, activations, RoPE, exp and the conv1d are excluded; they are small in FLOPs but not in vector-engine time. The GEMM work is exactly 2 × 1,372,717,056 matmul parameters = 2.745 GFLOP per token, independent of L. Two cores depend on the sequence. Attention costs 2 · 2 · 8 heads · 256 · (keys seen) per query token, which totals 4,096 · L² per layer per causal sequence (4,096 · L per token on average). The GDN core costs 16 · (10 · C · 128 + 6 · 128²) per token per layer.

10. Implications for porting to Trainium2

This section sticks to what follows from the model and the code. Where it cites a kernel, it means the local ext/nki-library tree (nkilib). It quotes no throughput or latency figures.

10.1 The port boundary

The cleanest seam already exists. hidden_engine.Backend.forward(state, questions, rows) must "run each question as a continuation of the state, seeing no other question", and return the final, post-norm hidden states at the given rows (each option's last token, then <answer>) as [len(rows), 2048]. HiddenStateEngine does everything else on the host, in numpy, with the same prompting, fitting and confidence code. That includes the pointer head in float64, the temperature and the softmax. A Neuron backend that implements this one method gives a working decider. Moving the head onto the device later is optional and small.

10.2 Workload shape

  • Prefill only. There are no decode kernels (gdn_tkg, attention_tkg), no KV paging and no cross-request cache. At most there are two passes per request: the prefix, then a batch of suffixes against it.
  • Compute versus bandwidth. A forward over T tokens reads about 2.75 GB of bf16 weights and performs about 2.75 GFLOP × T, which is roughly T FLOP per weight byte. Below the device's ridge point (peak FLOP/s ÷ HBM bytes/s), a forward is weight-bandwidth-bound. Above it, it is compute-bound. Batched requests (m rows × L) and long states move a forward toward compute-bound. Small single-question requests sit on the bandwidth side.
  • The GEMMs come first. 94–97% of FLOPs sit in a handful of GEMM shapes (8 per GDN layer, 7 per attention layer) with K = 2,048 or 6,144 and N ∈ {16, 512, 2,048, 4,096, 6,144}. in_proj_a and in_proj_b (N = 16) are tiny; concatenate them with in_proj_z, or with in_proj_qkv, into one projection.

10.3 Gated DeltaNet on NeuronCores

  • Chunked core. nkilib.experimental.gdn.gdn_cte implements this recurrence. The default "schur" algorithm uses CHUNK = 128 and requires S to be a multiple of 128 and Dk, Dv ≤ 128 (here 128 and 128). It forms (I + A)⁻¹ by a recursive Schur-complement merge with no matrix powers. Inputs must arrive L2-normalised, with the query scale passed as scale = 1/√128. g and β are fp32. The output is un-normalised, so the gated RMSNorm with z, and out_proj, must follow as a separate epilogue. recurrent_state is an optional fp32 in/out buffer, which is exactly what the suffix pass of the shared prefix needs. The "neumann" variant (CHUNK 64, 16 × 16 nilpotent blocks) cannot take an initial state, so it cannot serve the suffix pass.
  • Conv1d. gdn_conv1d_prefill maps channels to partitions (6,144 = 48 tiles of 128) and time to the free axis, and does the 4 taps as per-partition scalar multiply-accumulates on the vector engine, fusing SiLU. It returns the conv state as the last K raw columns, matching what HF caches.
  • Glue that remains. This means the per-head l2norm of q and k (eps 1e-6 inside the rsqrt), g = −exp(A_log)·softplus(a + dt_bias) and β = σ(b) on [L, 16], the layout change from channel-major conv output to head-major q/k/v, and the gated norm.
  • Numerics validation. The intra-chunk inverse is where ports go wrong. Test on real activations from the checkpoint, not random tensors: the Neumann-product bug recorded in mps_kernels.py passed random tests and failed by up to 5e8 on real inputs.

10.4 Attention

  • Split the d = 256 contraction into two 128-row tiles; attention_cte supports d ≤ 512. RoPE touches only the first tile (dims 0–63).
  • GQA 4:1. One K/V tile serves 4 query heads.
  • The suffix pass needs prior K/V, which attention_cte takes as k_prior/v_prior with a used length. Positions must continue from the real prefix length.
  • Fuse ⊙ σ(G) before o_proj. Apply the zero-centred QK-norm before RoPE. De-interleave q_proj per head.

10.6 Static shapes, bucketing and padding

  • Ranges. The total sequence is 1 to 4,096 tokens (state + longest question). There are at most 32 questions per chunk (the max_batch default). Options run to 255 for a choice and 10 for a score, and every question has its decide row. The 248,320-row vocabulary gather is shape-independent.
  • Buckets. Compiled Neuron graphs want a small set of shapes. The Schur GDN kernel needs S to be a multiple of 128, so sequence buckets should be multiples of 128 (or powers of two from 128 to 4,096), with question-count buckets for m.
  • Right-pad, like the reference. For outputs at real positions, causal attention and the causal recurrence make trailing pads harmless. Pads must still be masked as attention keys.
  • Pads before a reused state are a trap. In the reference's batched rows, pads are zeroed before the projections, but they still produce β = σ(0) = 0.5, a nonzero decay, and conv outputs that mix in the last real tokens. They do change the final recurrent state. That is harmless there, because the final state is discarded. If a port pads the prefix to a bucket and then forks its state, it must neutralise the pads (β = 0 and g = 0 at pad positions, so the state passes through unchanged), take the conv state from the last 3–4 real columns, mask the pad keys in the cached K/V, and start the suffix positions at the real L_s.
  • Gather indices. These are the last real token per row (not the bucket end) and the option indices relative to whatever was forwarded (offset by L_s on the batched path).

10.7 What to load, and what to skip

Load the 24 text decoder layers, the final norm, the embedding table, the pointer head and, if not pre-merged, the LoRA adapter. Skip model.visual.* (331.4M), mtp.* (60.8M) and the LM head, which is tied, so no separate tensor exists. Merging LoRA offline turns the served torso into a plain Qwen3.5-2B text decoder with changed weights, so a generic Qwen3.5 text-model port plus the pointer head is enough.
